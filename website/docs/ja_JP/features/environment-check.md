# 環境チェック

> 0.0.7 以降で利用可能。ネイティブ UI（WebView ではありません）。

環境チェックは、**通常の未承認アプリがデバイスで実際に何を見られるか**を報告します。root マネージャーに見えるものではありません。

## 視点が重要な理由

KernelSU の root 隠蔽は **UID 単位で分離**されています。マネージャーは root を持ちファイルシステム全体を見られますが、未承認アプリはフィルタされた视图を見ます——モジュールファイルはアンマウントされ、root バイナリは隠されています。

マネージャー自身の視点でスキャンしても「このデバイスは root 化されている」と分かるだけで、何の価値もありません。環境チェックはプロセスを fork して**未承検 UID に降権**させ、その視点でデバイスを観察します。そのため結果は、検出対象（銀行アプリ・ゲームのアンチチート）が実際に直面する露出面を反映します。

## 場所

**「セーフティ」タブ → 環境チェック**。

「チェック開始」を押すとプローブが実行され、結果が一覧で表示されます：

| 状態 | 意味 |
|---|---|
| 露出 | 未承認 UID がこの痕跡を観察できる |
| クリーン | この視点では痕跡が見えない |
| 未検証 | プローブが这个项目をチェックできなかった（SELinux 制限など） |

各項目には観察内容の短い説明が付き、対処できます——たとえばモジュールマウントが露出していれば、「スーパーユーザー」でそのアプリのプロファイルを開き「モジュールをアンマウント」を有効にします。

## チェック項目

- `su` 実行ファイル（`/system/bin/su`、`/system/xbin/su`、`/data/adb/ksu/bin/su`）
- `/data/adb` と `/data/adb/ksu` へのアクセス
- `/proc/self/mounts` に見えるモジュールマウント
- `ksud`、`zygiskd`、`muz-*` プロセスの可視性
- SELinux enforce 状態、`ro.debuggable` / `ro.secure`
- `/sbin/magisk`、`/.magisk` などの一般的な検出パス

## 制限——必ずお読みください

これは**診断レポートであり、保証書ではありません**：

- ローカルの静的な痕跡のみを調べます。Play Integrity、サーバー側のリスク判定、動作検出はチェックできません。
- 特定のアプリが必ず通過するとは限りません。アプリはそれぞれ独自の検出ロジックを持ちます。
- プローブが降権できない場合（まれ、SELinux に依存）はコマンドが明示的にエラーを返し、**偽の「すべて安全」を返すことはありません**。

価値は実行可能であることです——どのベクトルが露出しているか、次にどこへ行くべきか（通常はアプリのプロファイル設定）を教えてくれます。
