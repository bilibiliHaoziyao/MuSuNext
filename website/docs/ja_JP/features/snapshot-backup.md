# スナップショットのバックアップと復元

> 0.0.7 以降で利用可能。ネイティブ UI（WebView ではありません）。

スナップショットは環境設定をバックアップし、機種変更や ROM 書き換え後にワンクリックで復元するためのものです。モジュールを探し直したり、アプリに再度権限を付与したりする必要がありません。

## 含まれる内容

| 項目 | 詳細 |
|---|---|
| モジュール | インストール済み各モジュールの id と有効/無効状態 |
| root 承認 | すべてのアプリプロファイル（uid、allow_su、gid/groups、SELinux コンテキスト） |
| 内蔵コンポーネント | MuZygisk / MuMount のオン/オフ状態 |

スナップショットにはモジュール zip、アプリデータ、システムイメージは**含まれません**。設定状態のみを記録します。復元を適用するには、モジュールがすでにインストールされている必要があります。

## 場所

**「設定」→「バックアップと復元」**（バージョンによっては「セーフティ」タブの入口内）。

- **作成**：`/data/adb/ksu/snapshot/` に `snapshot-<タイムスタンプ>.tar.gz` を書き出し、件数とサイズを記録したマニフェストを含めます。
- **一覧**：各スナップショットの時刻、モジュール/承認/コンポーネント件数、サイズを表示。
- **復元**：選択したスナップショットの状態を適用。
- **削除**：スナップショットファイルを削除。

## 復元は破壊的な操作です——注意

復元の前に、MuSu は現在の状態を **`.pre-restore` スナップショットとして自動作成**します。必要ならロールバックできます。UI は再確認を求め、上書きされる内容を明示します：

- モジュールの有効/無効フラグ
- root 承認リスト全体
- MuZygisk / MuMount のスイッチ

復元成功後は**フル再起動**を求められます。モジュールのマウント状態と root 設定は起動時に完全に適用されます。

## 典型的な流れ

1. ROM 書き換えや機種変更の前に：**作成**。
2. 新しい環境に同じモジュールを入れた後：**復元**。
3. フル再起動し、モジュール状態とアプリ権限を確認。
4. 問題があれば `.pre-restore` スナップショットを復元してロールバック。
