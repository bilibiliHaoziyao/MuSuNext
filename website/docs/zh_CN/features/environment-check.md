# 环境检测

> 自 0.0.7 起提供。原生界面，非 WebView。

环境检测报告的是：**一个普通的、未授权的应用，在你的设备上实际能看到什么**——而不是你的 root 管理器能看到什么。

## 为什么视角很重要

KernelSU 的 root 隐藏是**按 UID 隔离**的。你的管理器有 root，能看到完整文件系统；未授权应用看到的是过滤后的视图——模块文件被 umount，root 二进制被隐藏。

如果站在管理器自己的视角扫描，只能证明"这台设备已 root"——这没有任何价值。环境检测会派生一个探针进程，**降权到未授权 UID**，透过这个视角观察设备，因此结果反映的是检测目标（银行 App、游戏反作弊）真正面对的暴露面。

## 在哪里

**「安全」Tab → 环境检测**。

点「开始检测」运行探针，结果以列表呈现：

| 状态 | 含义 |
|---|---|
| 已暴露 | 未授权 UID 能观察到该痕迹 |
| 干净 | 从该视角看不到该痕迹 |
| 未验证 | 探针无法检查该项（例如受 SELinux 限制） |

每项都有一行简短说明，告诉你观察到了什么，便于采取行动——例如，如果某个模块挂载被暴露，就去「超级用户」里打开那个应用的配置，为它启用「卸载模块」。

## 检测项

- `su` 可执行文件（`/system/bin/su`、`/system/xbin/su`、`/data/adb/ksu/bin/su`）
- `/data/adb` 与 `/data/adb/ksu` 是否可访问
- `/proc/self/mounts` 中可见的模块挂载
- `ksud`、`zygiskd`、`muz-*` 进程是否可见
- SELinux enforce 状态、`ro.debuggable` / `ro.secure`
- 常见检测路径，如 `/sbin/magisk`、`/.magisk`

## 局限——请务必阅读

这是一份**体检报告，不是免检证书**：

- 只覆盖本地静态痕迹，无法检测 Play Integrity、服务端风控或行为检测。
- 结果不保证某个具体 App 一定能通过——App 有各自的私有检测逻辑。
- 如果探针无法降权（罕见，取决于 SELinux），命令会明确报错，**绝不会返回伪造的"全部安全"**。

它的价值在于可执行：告诉你哪些向量已暴露、下一步该去哪里（通常是某个应用的配置）。
