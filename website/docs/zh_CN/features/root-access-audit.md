# Root 访问审计

MuSu Next 在管理器底部栏正中新增了「安全」Tab，专门用来回答一个问题：**我的设备上，谁在用 Root，什么时候用的，用了多少次？**

相比逐个翻看原始的 SU 日志，安全 Tab 把散落的记录按应用聚合，一眼就能看出哪些 App 频繁调用 Root。

## 打开审计

进入「安全」Tab，顶部状态卡片会显示审计的开关状态：

- **审计已启用**：内核正在把 Root 相关事件写入 `sulog` 日志文件，下方统计会持续更新。
- **审计未启用**：点击「启用审计」即可打开记录功能。

审计依赖内核的 `sulog` 事件通道。启用后无需重启，新的 Root 请求会立即开始记录。

## 按应用查看

状态卡片下方是「按应用」列表。每一条代表一个发起过 Root 请求的应用，显示：

- **应用标识**：进程的 `comm`（或可执行文件名 `exe`）
- **调用次数**：该应用累计触发的 Root 事件总数
- **最近调用时间**：最后一次请求的时间
- **事件分类标签**：按类型拆分计数
  - `root_execve`：Root 环境下执行命令
  - `sucompat`：`su` 兼容调用
  - `ioctl_grant_root`：通过 ioctl 授予 Root

列表按调用次数从高到低排列，最常用的 Root 应用排在最前面。进入页面时会自动刷新，也可以下拉手动刷新。

## 查看逐条记录

如果想看每一次调用的详细原文（完整命令行、时间戳等），点击列表下方的「查看完整 SU 日志」，进入日志页逐条查看，支持按类型筛选与搜索。

## 与其他功能的关系

- **App Profile**：限制每个 App 的 Root 权限范围；安全 Tab 则记录实际发生的访问，两者配合可以既授权又留痕。
- **SU 日志**：安全 Tab 的聚合数据来自同一份 `sulog`，可在日志页查看原始记录并清理。

## 只想临时关闭 Root？

安全 Tab 是「事后审计」——记录已经发生的访问。如果你需要在某些场景（如银行 App、游戏反作弊）临时阻止 Root，可以使用 App Profile 对特定应用收回权限，而不是卸载模块。
