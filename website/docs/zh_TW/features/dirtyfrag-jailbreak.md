# 內建 DirtyFrag 一鍵越獄

MuSu Next 0.0.8 新增內建 **DirtyFrag 一鍵越獄**。它利用 CVE-2026-43284 頁面快取寫入漏洞載入 `dfroot.ko`，取得**重啟即失效的臨時 root**；不解鎖 Bootloader，也不刷寫任何分割區。

這是供研究使用的臨時 root，不是永久 root 方案。

## 從哪裡進入

首頁常駐「越獄」按鈕，點開即進入原生越獄介面（無 WebView，無需另外安裝管理器）。介面依序引導：

1. **相容性偵測**——判斷目前核心是否受支援。
2. **風險說明**——列出越獄會為裝置帶來哪些改變。
3. **風險二次確認**——真正執行前再次明確確認。
4. **一鍵越獄**——一次跑完整個流程，無需選擇管理器，也無需另裝外部管理器。

該載荷只啟動 MuSu Next 作為管理器，不用你挑管理器，也不用額外側載。

## 相容性

DirtyFrag 只為一組固定的核心模組介面（KMI）提供載荷：

- `android12-5.10`
- `android13-5.10`
- `android13-5.15`
- `android14-5.15`
- `android14-6.1`
- `android15-6.6`
- `android16-6.12`
- `android17-6.18`

KMI 相符只是初篩。廠商可能在保留相同 KMI 字串的情況下回移了修補，所以即使 KMI 相符，裝置仍可能無法越獄。內建偵測會給出明確結論；若裝置不受支援，「一鍵越獄」按鈕不可用。

## 風險——點擊前务必讀完

- **重啟後 root 完全消失。** 授權只在本次開機內有效，重啟後須重新跑一遍流程才會再有 root。
- **SELinux 會被設為 permissive。** 載荷會執行 `setenforce permissive`，整個開機週期內裝置都處於寬鬆的 SELinux 狀態。
- **70 秒內絶對不要重複點擊。** 漏洞利用視窗約 70 秒，期間重複點擊（或重開機）可能引發核心衝突，導致當機或重新啟動。執行過程中按鈕保持鎖定。
- **失敗時進入安全模式處理。** 開機進入安全模式，即可關閉或卸載該載荷。

## 授權與原始碼

DirtyFrag 載荷以**獨立 APK 散佈、無桌面圖示**，採用獨立的 **GPL-2.0-only** 授權，與 MuSu Next 本體的 GPL-3.0-or-later 程式碼相互獨立。原始碼：[MuSuNext-DirtyFrag](https://github.com/bilibiliHaoziyao/MuSuNext-DirtyFrag)。

## 限制

- 這是**研究用途的臨時 root**，不是永久 root 方案。
- 不解鎖 Bootloader、不刷寫分割區，也無法在重啟後保留。
- 不保證通過 Play Integrity 或任何服務端風控，各家應用程式有自己的私有偵測邏輯。

## 與其他功能的關係

- **環境檢測**：回報一個未授權應用程式實際能看到什麼，是獨立診斷，不依賴越獄狀態。
- **Root 存取稽核**：依應用程式記錄 Root 使用情況。越獄只在本次開機授予 root，稽核會記錄期間實際發生的存取。
