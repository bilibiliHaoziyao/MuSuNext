# 環境檢測

> 自 0.0.7 起提供。原生介面，非 WebView。

環境檢測回報的是：**一個普通的、未授權的應用程式，在你的裝置上實際能看到什麼**——而不是你的 root 管理器能看到什麼。

## 為什麼視角很重要

KernelSU 的 root 隱藏是**按 UID 隔離**的。你的管理器有 root，能看到完整檔案系統；未授權應用程式看到的是過濾後的視圖——模組檔案被 umount，root 執行檔被隱藏。

如果站在管理器自己的視角掃描，只能證明「這台裝置已 root」——這沒有任何價值。環境檢測會派生一個探針行程，**降權到未授權 UID**，透過這個視角觀察裝置，因此結果反映的是檢測目標（銀行 App、遊戲反作弊）真正面對的暴露面。

## 在哪裡

**「安全」分頁 → 環境檢測**。

點「開始檢測」執行探針，結果以列表呈現：

| 狀態 | 含義 |
|---|---|
| 已暴露 | 未授權 UID 能觀察到該痕跡 |
| 乾淨 | 從該視角看不到該痕跡 |
| 未驗證 | 探針無法檢查該項（例如受 SELinux 限制） |

每項都有一行簡短說明，告訴你觀察到了什麼，便於採取行動——例如，若某個模組掛載被暴露，就去「超級使用者」裡打開那個應用程式的設定，為它啟用「卸載模組」。

## 檢測項

- `su` 執行檔（`/system/bin/su`、`/system/xbin/su`、`/data/adb/ksu/bin/su`）
- `/data/adb` 與 `/data/adb/ksu` 是否可存取
- `/proc/self/mounts` 中可見的模組掛載
- `ksud`、`zygiskd`、`muz-*` 行程是否可見
- SELinux enforce 狀態、`ro.debuggable` / `ro.secure`
- 常見檢測路徑，如 `/sbin/magisk`、`/.magisk`

## 局限——請務必閱讀

這是一份**體檢報告，不是免檢證書**：

- 只涵蓋本機靜態痕跡，無法檢測 Play Integrity、服務端風控或行為檢測。
- 結果不保證某個特定 App 一定能通過——App 有各自的私有檢測邏輯。
- 若探針無法降權（罕見，取決於 SELinux），指令會明確報錯，**絕不會回傳偽造的「全部安全」**。

它的價值在於可執行：告訴你哪些向量已暴露、下一步該去哪裡（通常是某個應用程式的設定）。
