# Root 存取稽核

MuSu Next 在管理器底部欄正中央新增了「安全」分頁，專門回答一個問題：**我的裝置上，誰在用 Root，什麼時候用的，用了幾次？**

相較於逐條翻閱原始的 SU 日誌，安全分頁把分散的記錄依應用程式彙總，一眼就能看出哪些 App 頻繁呼叫 Root。

## 開啟稽核

進入「安全」分頁，頂部狀態卡片會顯示稽核的開關狀態：

- **稽核已啟用**：核心正在把 Root 相關事件寫入 `sulog` 日誌檔，下方統計會持續更新。
- **稽核未啟用**：點擊「啟用稽核」即可開啟記錄功能。

稽核依賴核心的 `sulog` 事件通道。啟用後無需重新啟動，新的 Root 請求會立即開始記錄。

## 依應用程式檢視

狀態卡片下方是「依應用程式」列表。每一筆代表一個發出過 Root 請求的應用程式，顯示：

- **應用程式識別**：行程的 `comm`（或可執行檔名 `exe`）
- **呼叫次數**：該應用程式累計觸發的 Root 事件總數
- **最近呼叫時間**：最後一次請求的時間
- **事件分類標籤**：依類型拆分計數
  - `root_execve`：在 Root 環境下執行命令
  - `sucompat`：`su` 相容呼叫
  - `ioctl_grant_root`：透過 ioctl 授予 Root

列表按呼叫次數由高到低排列，最常用的 Root 應用程式排在最前面。進入頁面時會自動重新整理，也可以下拉手動重新整理。

## 檢視逐筆記錄

如果想看每一次呼叫的詳細原文（完整命令列、時間戳記等），點擊列表下方的「檢視完整 SU 日誌」，進入日誌頁逐條查看，支援依類型篩選與搜尋。

## 與其他功能的關係

- **App Profile**：限制每個 App 的 Root 權限範圍；安全分頁則記錄實際發生的存取，兩者搭配可以既授權又留痕。
- **SU 日誌**：安全分頁的彙總資料來自同一份 `sulog`，可在日誌頁查看原始記錄並清理。

## 只想暫時關閉 Root？

安全分頁是「事後稽核」——記錄已經發生的存取。如果你需要在某些情境（如銀行 App、遊戲反作弊）暫時封鎖 Root，可以使用 App Profile 對特定應用收回權限，而不是卸載模組。
